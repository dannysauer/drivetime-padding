# Design docs

A design doc works through a large or contested choice before it is decided: the problem, the requirements in scope, the options including keeping the current approach, a comparison, and a recommendation. It is edited freely while open and frozen once decided or abandoned, with the resulting ADR linked from it.

There are none yet. The choices still open are listed in [`../open-questions.md`](../open-questions.md); the first candidate for a design doc is broker authentication from Apps Script to Cloud Run (Technical Design §21.7), which blocks public release.

Name each doc `YYYY-MM-DD-short-title.md` by the date it was opened.
